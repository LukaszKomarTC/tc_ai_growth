# INC-2026-07-27 — tossacycling.com WordPress compromise (spam-mailer + RCE)

**Status:** ACTIVE THREAT NEUTRALIZED (evidenced) — **NOT yet formally closed** (verification
pending, see the closure runbook). A working site proves availability, not security.
**Severity:** high (production e-commerce, 8-day dwell, outbound spam, RCE persistence).
**Scope:** `tossacycling.com` only, confirmed by fingerprint sweep of all five vhosts (the
other four not yet given the full checksum/timestamp treatment — see open items).

## Confidence statement

Everything below marked **[evidenced]** has supporting command output or log lines captured
during the 2026-07-27 remediation session. Items marked **[not verified]** are open and must
be closed before the incident is declared resolved. This document deliberately separates the
two — do not read "threat neutralized" as "incident closed."

## Entry vector [evidenced]

**WordPress REST Batch API (`/wp-json/batch/v1`).** The attacker batched requests to abuse a
vulnerable plugin route and create an admin account **without authentication**, then logged in
as it and used the normal `upload-plugin` admin capability to install a malicious plugin ZIP
containing a webshell.

- **Exact vulnerable plugin: NOT confirmed** — batch request bodies are not in access logs.
  Leading suspect is the **Gravity Forms suite** (7 GF plugins present, largest REST surface,
  includes User Registration; the WooCommerce-GF addon was outdated with a pending update).
  The fix does not depend on naming it (vector blocked + all plugins updated).
- The brute-force from `172.236.140.96` (`POST /wp-login.php`, all 200 = failed) was a
  **separate, unrelated** commodity attack — explicitly NOT the entry.

## Goal [evidenced]

**Spam relay + RCE.** The deployed shell (`class-wp-taxonomy-ee7d1b.php`) is a multi-tier spam
mailer (`$K='sm_...'`; sendmail-pipe → raw SMTP socket → PHP `mail()` fallbacks) with a hidden
`shell_exec` RCE mode. First shell commands probed mail capability (sendmail binary, port 25,
`mail()`, `disable_functions`, MX lookup). Consistent with the site's prior tobacco/pharmacy
SEO-spam history (INC-2026-02-01).

## Attribution

**Unknown and unknowable from this evidence.** We have attacker IPs (`104.196.104.214`
successful, `86.54.25.131` probe) but IPs = proxies/VPNs/compromised hosts. Pattern is an
**automated criminal exploit campaign**, not evidence of targeting Tossa Cycling specifically.

## Remediation performed [evidenced]

- **Core** reinstalled pristine; `wp core verify-checksums` → *Success* (after removing 2 shells
  hidden in `wp-includes/`: `class-wp-simplepie-file-resolver.php`, `assets/class-walker_c080dd89.php`).
- **Code** restored from the **July 18 (pre-breach) backup**, files-only, `wp-content/plugins` +
  `themes` only (kept pristine core, cleaned uploads, and current DB with orders). Restored
  files re-swept clean (fingerprint + hex-name).
- **Persistence removed** (all quarantined to `/root/quarantine/` with hashes): `lukasz` crontab
  (2 malicious lines), `object-cache.php`, wp-config injection block, DB row
  `_site_transient_health_b5592a35` (502 KB base64 payload), 12 uploads shells, 2 core shells,
  17 mu-plugins shells, fake plugin `widget-accessibility-helper-5fb784` (3 files), `/tmp/phpiAgloq`.
- **Rogue admins** 426 + 437 deleted; admin set confirmed = only ids 1, 119.
- **7 free plugins** updated to latest (6 premium pending licensed update — from clean backup, vector blocked so not an open door).
- **Hardening:** `mu-plugins/zzz-tc-security.php` disables `batch/v1`; `WP_DEBUG=false`,
  `DISALLOW_FILE_EDIT=true`; firewall deny `172.236.140.96`; autodeploy timer stopped;
  registration confirmed off (default role Customer).
- **Secrets rotated:** WP salts, DB password (wp-config synced), 2 admin passwords, SMTP
  (mailbox + `WPMS_SMTP_PASS`), `TC_GROWTH_SIGNING_KEY` (wp-config + both orchestrator files, perms preserved).
- **Email:** test delivered to Gmail **inbox** → reputation likely intact (low spam volume or short window).
- **Backups preserved:** 569 MB DB dump + 19 GB full current-state (both pre-restore).

## Open items — required before formal closure [not verified]

2. **SSH `authorized_keys`, `/etc/passwd` new users, systemd units/timers** — only crontab was reviewed.
3. **Outbound mail queue + mail logs** — mailer files removed, but queue not flushed/inspected.
4. **Other 4 subscriptions** (dashboard/tourdegirona/dev.tourdegirona/zelcycling) — only fingerprint-grepped, which we proved misses variants; need full checksum/timestamp pass.
5. **Orchestrator** `/opt/tc_ai_growth` (`tcgrowth` user) — signing key rotated but filesystem not scanned.
6. **DB triggers/stored routines** — only `wp_options` content was scanned.
7. **Clean baseline** created *after* verification; **restore-test** on staging; **several clean days** of monitoring.

## Corrections to earlier advice

- The 19 GB compromised backup does **not** "cost nothing." It holds live malware and possibly
  customer PII. Label `DO_NOT_RESTORE-COMPROMISED-2026-07-27`, `sha256sum` + record, `chmod 600`,
  set a deletion date (~2 weeks), and **exclude from operational backups**. Same for `/root/quarantine/`.

## Platform impact

Release 0.3 gate **remains suspended** — the VPS hosts the orchestrator and connector, and was
under attacker control today. Do not resume the integration programme until this incident is
formally closed (open items above) and the box is re-baselined as trusted.
