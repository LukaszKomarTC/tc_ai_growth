# Agent Attribution and Authority Protocol

This repository is operated through multiple AI systems that may post to GitHub using the owner's connected account. GitHub's visible author field is therefore not sufficient evidence of who produced a comment or what authority it carries.

## Mandatory identity header

Every AI-generated pull-request review, issue comment, design response, implementation summary, or automated governance note MUST begin with an explicit identity block:

```text
Actor: <ChatGPT Reviewer | Claude Builder | Codex Engineering Reviewer | other named agent>
Role: <review / implementation / audit / CI / product analysis>
Authority: <recommendation only | implementation only | no owner authorization>
Posted through: Łukasz's connected GitHub account
```

A footer such as "Generated by Claude" may remain, but it does not replace the header.

## Role boundaries

### Owner — Łukasz

Only the owner may:

- authorize merges to `main`;
- authorize production deployment or production-write capability;
- approve business decisions, pricing, customer commitments, refunds, bookings, or policy exceptions;
- change governance authority;
- declare an acceptance gate complete when the protocol assigns that authority to the owner.

### Claude Builder

Claude may design, implement, test, document, open pull requests, respond to review, and recommend a course of action. Claude has no merge, deployment, production-write, or owner-decision authority.

### ChatGPT Reviewer

ChatGPT may inspect repository state, review architecture, security, governance, operations, product usability, and business impact, and post recommendations with acceptance criteria. ChatGPT has no merge, deployment, production-write, or owner-decision authority.

### Codex Engineering Reviewer

Codex may inspect code, run or interpret engineering checks, identify defects, propose patches, and submit technical review. Codex has no merge, deployment, production-write, or owner-decision authority unless a future governance amendment explicitly grants a narrow capability.

## Required review format

AI reviews should use this structure where applicable:

1. **Finding** — what is wrong, missing, or uncertain.
2. **Risk** — operational, security, legal, cost, maintainability, UX, or business impact.
3. **Recommendation** — the specific change proposed.
4. **Acceptance criteria** — objective conditions for closure.
5. **Verdict** — for example: `safe for owner authorization`, `do not merge yet`, or `non-blocking observation`.

The verdict is a recommendation only unless the owner explicitly posts the authorization.

## Reserved authority language

AI-authored comments MUST NOT present these words as if spoken by the owner:

- `authorized`
- `owner approved`
- `merge it`
- `deploy`
- `production change approved`
- `gate closed by owner`

An agent may write `recommended for owner authorization` or quote an already-recorded owner decision with a direct reference.

## Audit rule

Reviewer input is not authorization. Builder output is not acceptance evidence by itself. GitHub comments posted through the owner's account must be interpreted according to the identity header and this protocol, not the visible GitHub username.

## Codex and agent workflow

Codex and other repository-aware agents must read this file before reviewing or modifying the repository. Pull-request templates, automation prompts, and future bot integrations should reference this protocol. Dedicated GitHub App or bot identities remain the preferred long-term solution; this header protocol is the immediate control while agents share the owner's GitHub identity.
